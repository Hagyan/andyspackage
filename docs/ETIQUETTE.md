# Etiquette for Andy's Notes

Living document for mathematical notation, proof presentation, and project workflow.

## Mathematical notation

- Write the mathematical script italic \varphi; avoid \phi because it resembles the empty set too closely.
- Use \RR^* for \RR\setminus\{0\}, and \RR^{**} for the positive real numbers.
- The preferred natural-number conventions include \NN^*, \NN^+, and \NN_0. For integers, \ZZ^* and \ZZ^{**}=\ZZ^+ are useful.
- In general, follow the logicians' convention that \NN contains zero. Zero-index sets and sequences where appropriate. State the convention locally if ambiguity is possible.
- Keep semantic consequence and derivability distinct: \Gamma\entails\varphi and \Gamma\proves\varphi.
- Prefer the established package notation (\NN, \ZZ, \QQ, \RR, \CC, \tuple, \struc, \set) where it improves consistency.

## Proofs and tombstones

The tombstone is a proof-ending mark with two independent dimensions: fill records how a proof relates to its source and its level of originality; the small tag below records provenance.

| Tombstone | Meaning |
| --- | --- |
| Hollow | Quoted from or closely following a cited source (“by the book”) |
| Striped | General proof |
| Solid light purple | Highly original contribution |

For a biconditional, prove the two directions separately with IffForwardProof and IffBackwardProof. Each direction ends with a half-striped tombstone and an arrow marking its direction.

For N cases, write \begin{CaseProof}{N}. It prints “Proceed by cases.” Each AndyCase is labelled with a lowercase Roman numeral and ends with a progress tombstone. The hatch advances horizontally, and the fraction reports completed cases. Supply all N cases; the package cannot infer when the argument is complete.

Example:

~~~latex
\begin{CaseProof}{3}
\begin{AndyCase}
First case.
\end{AndyCase}
\begin{AndyCase}
Second case.
\end{AndyCase}
\begin{AndyCase}
Third case.
\end{AndyCase}
\end{CaseProof}
~~~

Provenance tags:

- QED: proof written and verified by a human.
- XM: Ex machina, generated by a machine with little or no human alteration.
- AXM: Auxilium ex machina, machine assistance with meaningful human direction, revision, or verification.

Use \AndyTombstoneFootnote for a concise footnote and \AndyProofNotationAppendix for the longer addendum entry. The default proof-ending mark is striped QED; use \AndyBookMark[XM], \AndyGeneralMark[AXM], or \AndyOriginalMark[QED] for other combinations.

Use \AndyOrnamentBreak to insert the Angus-inspired ornamental divider. It is a manual section break and can be omitted from short assignments.

## Headers and fonts

The bookish purple running header is the default. Select header=plain, header=minimal, or header=none in the andysnotes package options. The minimal header contains document title, current section as §1, author (default convention: Andrew M. Hagy), date, and class. Student ID is hidden unless studentid=true is set and \AndyStudentID{...} is supplied. Page number stays in the footer.

Times is the default. The alternate font=typewriter mode follows the supplied 1967 dissertation: typewritten prose, generous line spacing, indented paragraphs, and traditional math symbols that look separately typeset into the text. This is the starting point for the nostalgic presentation; tune it as examples accumulate.

## Handwritten pages and images

Scanned notes can be included as images in the project. Put image files in a folder such as images/, load andyspics (or graphicx), then write:

~~~latex
\begin{figure}[htbp]
  \centering
  \includegraphics[width=.95\linewidth]{images/handwritten-page-01.jpg}
  \caption{A handwritten page.}
\end{figure}
~~~

Overleaf supports common image files such as PDF, PNG, JPG, and JPEG. Keep image filenames simple and upload them into the project alongside the source.

## Editing and publishing

1. Keep a local clone of https://github.com/Hagyan/andyspackage or edit in GitHub Codespaces.
2. Edit the .sty files, main.tex, examples, or this guide. Compile main.tex locally or in Overleaf to catch errors.
3. Commit and push your change to GitHub. In Codespaces, review the diff, commit, and sync changes; a commit that stays only in Codespaces is not published.
4. For Overleaf, upload or replace the updated package file in the project and recompile. Existing Overleaf projects contain copies and do not update automatically from GitHub unless connected to the repository.

For a local command-line workflow:

~~~sh
git clone https://github.com/Hagyan/andyspackage.git
cd andyspackage
# edit, then compile with the project files available
pdflatex main.tex
git add andysnotes.sty main.tex docs/ETIQUETTE.md
git commit -m "Add proof tombstones and style options"
git push
~~~

Update this document whenever a convention changes. It is a living guide, not a rigid rulebook.
